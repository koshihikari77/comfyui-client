# AREA / COUPLE のハマりどころ

## 0. ★ノードが `PCTextEncode` のままスケジュールを書いている（最重要）

- 症状: `[AND AREA(...):COUPLE(...):0.3]` を書いたのに分離しない／絵が崩れる／ゴミが混じる。**エラーは出ない**
- 原因: `PCTextEncode` は **scheduling 非対応**（表示名も "PC: Text Encode (no scheduling)"）。
  `encode_prompt()` は `parse_prompt_schedules` を呼ばず `AND` で split するため、`[` `:0.3]` がリテラル token として残り、AREA と COUPLE が同時適用される
- 対処: workflow のノードを **`PCLazyTextEncode`（PC: Schedule Prompt）** に差し替える
- 予防: **書く前にノード型を確認**。`DEF` マクロも `PCTextEncode` では展開されない

## 1. ★COUPLE の座標を AREA と同じ数字で書いている

- 症状: 片方の領域が丸ごと効かない／反転する
- 原因: `AREA(x 幅)` と `MASK・COUPLE(x1 x2)` は**座標系が違う**のに数字を写した
  - `COUPLE(0.5 0.5)` = 始点0.5→終点0.5 = **幅ゼロのマスク**
  - `COUPLE(0.4 0.2)` = 始点>終点 = **反転**
- 対処: 右半分は `AREA(0.5 0.5)` / **`COUPLE(0.5 1)`**

## 2. ★隙間（gap）のルールを取り違える（COUPLE と AREA で逆）

- **COUPLE / MASK 単体** → **隙間を空ける**（`COUPLE(0 0.45)` / `COUPLE(0.55 1)`）。密着させるとキャラが隣へはみ出し融合する
- **AREA 単体（単純分割）** → **密着させる**。隙間を作るとそこに base だけが強く出て、AI が勝手に何か描く
- **AREA:COUPLE スケジュール** → 密着でよい。**隙間を作るなら `FILL()` が必要**

## 3. `split screen` を一枚絵に入れてしまう

- 症状: 意図せず画面が分割・コマ割りされる
- 原因: `split screen` / `comic` / `multiple views` は **区切り線を生じさせるタグ**
- 対処: **一枚絵にしたいなら入れない**（入れなければ境目はぼかされ馴染む）。
  これらは**縦（上下）分割の融合対策**として使うもの。横長の一体シーンでは使わない
- 入れる場合も `[:split screen:0.3]` と遅らせる（最初から効かせると分割が強すぎる）

## 4. AREA だけで最後まで通している

- 症状: 淡い・未完成・コラージュ感。境界が硬い。背景や衣装が領域ごとにバラバラ。生成が遅い
- 原因: AREA は**領域ごとに別生成して合成**する方式（latent 方式）
- 対処: `[AND AREA(...):COUPLE(...):0.3]` にして **AREA 期を最小化**し、以降 COUPLE で馴染ませる

## 5. TIMING の意味・値を取り違える

- `step` は 0〜1 の比率。**1 より大きい整数は絶対ステップ番号**（`[A:B:4]` = 4 ステップ目から）
- 総ステップ数依存: 30step なら 0.2 でも可、15step では 0.3 でも早すぎることがある
- 大きくするほど分離は強いが、**遅くなる**＋**別背景・別衣装が残りやすい**

## 6. base にキャラ固有タグを書いている

- 症状: 髪色・目の色・服が隣の領域に漏れる／混ざる
- 原因: COUPLE/MASK 時、base は**全域に効き領域へ滲む**
- 対処: 髪色・目・服は**各領域のプロンプトだけ**に書く。base は背景・シーン・画質のみ。
  領域が全面を覆わない場合は `FILL()` で base を領域外に限定する

## 7. 人数タグが悪さをする

- 症状: 「右端に2人＋中央に1人」のような誤配置。逆に融合
- 対処: `2girls` は必須ではない。**削る**／**`(2girls:1.1)` と強調する**の両方を試す。
  ネガに `solo` を入れると融合しにくくなる

## 8. ブロック境界を誤る

- 症状: ある prompt が別領域に食い込む
- 原因: **AND から次の AND / BREAK / 終端までが 1 ブロック**という前提を見落としている
- 対処: 1 ブロック 1 領域として読む。COUPLE 形式では `base COUPLE(...) A COUPLE(...) B`

## 9. 領域が小さすぎる

- 症状: その領域に何も描かれない
- 原因: **0.1 以下の極小領域は AI が諦める**（縦横とも）
- 対処: 領域を広げる

## 10. fp8 で COUPLE がエラー

- 対処: **fp16 にする**（MASK / AREA 単体は fp8 でも動く）
- `PC: Attention Couple (batch negative)` は**必須ではない**（性能最適化のみ）

## 11. `COUPLE AREA()` と書こうとする

- 書けない。AREA と COUPLE は**スケジュールで切り替える**

## 12. 座標のカンマ区切りを間違える

- `(x1, x2, y1, y2)` のように全部カンマ区切りにしない。正しくは **`(X座標のペア, Y座標のペア)`**
- **エラーが出ずに誤動作する**ので気づきにくい

## 13. 複数キャラの LoRA 干渉

- 症状: char LoRA を複数同時適用して髪色・顔が混ざる
- 原因: LoRA はモデル自体を書き換えるため、**エリア分けとは別問題**
- 対処: LoRA 強度を落とす／LoRA をスケジュールする／**ベースを作ってからキャラごとに inpaint**
